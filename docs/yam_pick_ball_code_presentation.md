# YAM Ultra 可变形球抓取与放置：代码讲解正文

本文按一次 episode 的实际执行顺序解释工程代码。主线采用“抓起软球并放到方块上”模式；只检查场景、只抬升和放回桌面的模式在相应位置说明。参数和判据以当前源码为准。

| 文件 | 作用 |
| --- | --- |
| [scripts/yam_pick_ball.py](../scripts/yam_pick_ball.py) | 启动仿真、建场景、采样与复位、运动控制、抓取放置和结果验收 |
| [yam_kinematics.py](../source/yam_ultra_deformable_place/yam_ultra_deformable_place/yam_kinematics.py) | 根据 URDF 参数实现前向运动学、几何雅可比和 DLS 逆运动学单步增量 |

# 一、整体运行流程：一次 episode 怎样完成

## 1. 启动与建场景

主程序先解析运行模式，然后尽早启动 AppLauncher，之后才导入依赖 Kit 环境的仿真模块。[make_sim()](../scripts/yam_pick_ball.py#L405) 创建 Newton 仿真上下文；[spawn_scene()](../scripts/yam_pick_ball.py#L458) 放入桌面、YAM 机器人、动态方块和 VBD 软球；sim.reset() 初始化仿真。机器人资产来自事先转换好的 USD，主任务运行时不会重新执行 URDF 转换。

main 检查参数组合是否合法，并依据命令行开关决定本轮做到哪一步：

| 模式 | 主要执行范围 |
| --- | --- |
| 默认 | 随机复位、等待场景稳定、检查场景状态 |
| --gripper-check | 场景稳定后单独检查夹爪张开和闭合 |
| --pick-lift | 抓取并抬升软球 |
| --pick-lift --put-back | 抬升后将球放回原桌面位置 |
| --pick-lift --place-on-block | 抬升后将球搬运至动态方块顶面 |

## 2. 一次 episode 的状态图

    sample_object_positions
      → reset_episode
      → wait_until_scene_settled
      → PRE_GRASP
      → DESCEND
      → CLOSE_GRIPPER
      → QUICK_GRASP_CHECK
      → LIFT
      → 可选：RAISE_FOR_TRANSFER
      → TRANSFER_TO_BLOCK / RETURN_ALIGN
      → 可选：BALL_ALIGNMENT_CORRECTION
      → LOWER_TO_BLOCK / LOWER_TO_TABLE
      → RELEASE
      → RELEASE_SETTLE
      → RETREAT
      → 最终物理验收
      → EPISODE_COMPLETE

这是对程序执行流程的状态机表达。代码通过 [main()](../scripts/yam_pick_ball.py#L1933)、[pick_and_lift_ball()](../scripts/yam_pick_ball.py#L1411) 和 [put_ball_back()](../scripts/yam_pick_ball.py#L1615) 的调用与分支推进，并用 STATE 日志标记阶段；没有单独定义状态枚举类。

每个阶段都遵循相似的控制逻辑：读取当前物理状态，计算目标或下发关节命令，推进若干物理步，再用真实状态判定是否可以继续。错误不是简单忽略：可恢复的单轮失败会记录发生阶段与机器人、方块、球的快照，然后进入下一轮；出现非有限数值或严重 CUDA 错误时，仿真状态不再可信，程序会停止。[step_scene()](../scripts/yam_pick_ball.py#L761) 还会在每个主物理步后检查关键张量是否出现 NaN 或 Inf。

# 二、核心运动学：FK、雅可比、IK 与轨迹

## 3. 前向运动学 FK：给定关节角，求当前末端位姿

[forward_kinematics_and_jacobian()](../source/yam_ultra_deformable_place/yam_ultra_deformable_place/yam_kinematics.py#L116) 的输入是：

| 输入 | 形状 | 含义 |
| --- | --- | --- |
| root_pose_w | (N, 7) | 基座世界位置 XYZ 与 XYZW 四元数 |
| arm_joint_pos | (N, 6) | joint1～joint6 的当前角度 |

输出为 gripper link 的世界位置 (N, 3)、世界旋转矩阵 (N, 3, 3) 和几何雅可比 (N, 6, 6)。N 是同时处理的机器人实例数量；当前任务通常只有一个实例。

实现时先由基座位姿建立齐次变换。对每个关节，再依次乘上 URDF 中固定的 origin 平移与旋转，以及当前关节角绕其局部转轴产生的旋转。六个关节都处理完之后，累积变换就是 gripper link 的世界位姿。代码中的 JOINT_ORIGINS_XYZ、JOINT_ORIGINS_RPY 和 JOINT_AXES 分别来自 URDF 的关节原点平移、原点旋转和转轴。

在每个关节旋转前，函数记录该关节原点 p_i 与单位转轴 z_i 的世界坐标。对旋转关节，雅可比第 i 列为：

    线速度列：Jv_i = z_i × (p_gripper − p_i)
    角速度列：Jω_i = z_i
    末端速度：[v; ω] = J(q) · q_dot

雅可比前 3 行描述线速度，后 3 行描述角速度；列的顺序对应 joint1～joint6。FK 解决的是“当前关节角使末端在哪里”，雅可比进一步回答“关节角微小变化会让末端怎样移动”。

## 4. 夹爪的朝向和真正抓球的位置

可以把 gripper 想成机械臂末端的一只手。手腕带着整只手转动，手上的夹持位置也会跟着移动。

FK 首先算出 gripper 原点的位置和整只夹爪的朝向。真正夹球的位置固定在 gripper 原点下方 12.5 cm，写在夹爪自己的局部坐标里：

    局部偏移 = (0, 0, −0.125) m

这个偏移是相对夹爪的，所以不能直接从世界坐标的 Z 值里减 0.125 m。要先看夹爪当前朝向，把局部偏移转到世界坐标，再加到 gripper 原点：

    抓取点世界位置 = gripper 原点世界位置 + 夹爪旋转矩阵 × 局部偏移

因此抓取点在球附近，而 gripper 原点可以在它上方。这里的“目标姿态”可以理解为夹爪要摆成的样子：夹指从上向下接近球，同时夹爪的水平朝向跟着球相对机器人的方位转动。它描述的是夹爪朝哪儿，不是抓取点的位置。

这里要区分两件事：

1. **夹爪朝哪儿**：用 gripper 的旋转矩阵 R_gripper 描述。它表示夹爪自身坐标轴在世界里的方向。
2. **夹爪在哪里夹球**：用抓取点的位置 p_grasp 描述。抓取点是夹爪上的一个固定点，没有另一套独立的朝向；它跟着整只夹爪一起转。

例如，手腕旋转时，gripper 原点可能只移动一点，但离原点 12.5 cm 的抓取点会走一段弧线。代码因此不只修正抓取点的位置，也修正它的雅可比：

    r_world = R_gripper × 局部偏移
    抓取点线速度 = gripper 原点线速度 + 角速度 × r_world

如果雅可比仍使用 gripper 原点的线速度，IK 就会以为“抓取点和原点移动得一样”，忽略抓取点随手腕旋转产生的弧线，控制位置会有偏差。这部分由 [grasp_point_kinematics()](../scripts/yam_pick_ball.py#L898) 完成。

## 5. 逆运动学 IK：根据末端偏差调整关节

可以把 FK 和 IK 看成两个相反方向的问题：

- FK：已经知道六个关节各转了多少，计算夹爪现在在哪里、朝向哪里。
- IK：已经知道希望抓取点去哪里、夹爪要朝哪儿，反过来计算六个关节应该怎样调整。

比如人伸手去拿桌上的杯子，眼睛先发现手离杯子还有一段距离，大脑再协调肩、肘、腕一起调整。机器人也类似：目标是末端的位置和朝向，IK 要把这个“末端还差多少”换算成多个关节的小幅调整。因为几个关节可以互相配合，通常也可能有多种姿势到达同一个位置，所以代码不是简单查出一个唯一答案，而是从一个初始姿势开始逐步修正。

雅可比矩阵可以理解成一张“局部动作说明表”：在当前姿势下，每个关节稍微转一点，会让抓取点往哪个方向移动、夹爪朝向怎样变化。程序把目标误差 e 和雅可比 J 交给阻尼最小二乘法，得到这一小步的关节角调整量：

    Δq = Jᵀ (J Jᵀ + λ²I)⁻¹ e

可以把式子读成：“参考末端还差多少，以及当前每个关节能怎样影响末端，算出一组协调的小调整。”其中：

- e 是目标位姿和当前位姿之间的差。只要求位置时是三维位置误差；同时要求朝向时，还会加入三维姿态误差。
- J 描述关节变化对末端变化的影响。
- Δq 是建议的关节角小变化，单位是弧度。它不是已经发生的真实运动，也不是速度或力。
- λ 是阻尼。机械臂伸直等特殊姿势下，有些关节变化可能很难让末端朝需要的方向移动；直接反推可能得到特别大的关节调整。阻尼会压住这种过大的调整，让求解更稳定。阻尼太大时，每一步也会更谨慎。

代码有两种控制要求：[damped_least_squares_position_step()](../source/yam_ultra_deformable_place/yam_ultra_deformable_place/yam_kinematics.py#L179)只关心“夹爪上的抓取点有没有到地方”；[damped_least_squares_pose_step()](../source/yam_ultra_deformable_place/yam_ultra_deformable_place/yam_kinematics.py#L207)还会同时关心“夹爪有没有摆成指定朝向”。可以把夹爪想成一只手：位置误差是手还差几厘米，姿态误差是手掌和手指的方向还差多少。旋转矩阵的三列分别记录夹爪自身 X、Y、Z 轴在世界里指向哪里；代码比较当前朝向和目标朝向对应的轴，估算该往哪个方向转一点。

预抓取时，[solve_approach_joint_target()](../scripts/yam_pick_ball.py#L1207) 从一组初始关节姿势开始，重复做 FK 和 DLS，最多迭代 300 次，得到预抓取关节目标。这一段只在数学模型中试算候选姿势，不推进仿真。初始的 joint1 根据目标方位调整，其余关节沿用预设姿态；候选角度会受关节限位约束。

机械臂真正运动时，[move_grasp_point()](../scripts/yam_pick_ball.py#L927) 每个物理步都重新读取实际关节角，重新计算抓取点当前位置和误差，再求一个小的 Δq。程序对调整量做限幅、把关节目标限制在关节范围内，再交给 position drive。Newton 推进一步后，真实关节位置可能因为驱动器、重力或接触载荷而没有完全跟上目标，所以程序会再读一次实际状态，继续修正。

因此，整段控制可以直观地理解为：

    看当前手在哪里
      → 看离目标还差多少
      → 估算哪些关节该往哪边调一点
      → 让仿真中的关节执行
      → 再看实际移动了多少
      → 重复，直到误差足够小且运动稳定

这就是本项目的闭环 IK：FK 提供当前状态，雅可比提供局部运动关系，DLS 计算关节调整，物理仿真执行后再反馈真实状态。

## 6. 目标轨迹怎样设置

先区分“目标轨迹”和“机械臂实际走过的轨迹”：目标轨迹是程序每个物理步希望末端或关节到达的位置；实际运动由关节驱动器和物理仿真产生，可能会有滞后。因此程序不是只规划一次就结束，而是不断用 FK、雅可比和 DLS 修正实际误差。

本工程主要有三种运动目标设置方式：首次预抓取先求关节目标，再在关节空间插值；接近、下降、抬升、下放和撤离主要设置抓取点的末端位置，并按需要同时设置夹爪朝向；夹爪开闭直接设置 joint7、joint8 目标；夹住球以后搬运则用连续极坐标路线。

### 6.1 首次预抓取：先算目标关节角，再在关节空间走过去

PRE_GRASP 的目标位置先设为当前球心上方 0.10 m，目标朝向由 radial_grasp_rotation 根据球相对机器人的方位设定。solve_approach_joint_target 先以种子关节角为起点，重复做 FK 和 DLS，最多迭代 300 次，算出一个能到达预抓取位姿的关节角目标。这个阶段只在数学模型中试算，不推进物理。

随后，[execute_arm_trajectory()](../scripts/yam_pick_ball.py#L1241) 从当前真实关节角 q_start 走向这个目标 q_goal。程序根据最大关节角差、ARM_JOINT_SPEED、物理步长和 motion_steps 估算步数；至少走 30 步。每步使用同一个平滑进度：

    u = 0 → 1
    α = 3u² − 2u³
    q_target = q_start + α(q_goal − q_start)

可以把它理解为：刚起步时慢一些，中间逐渐加快，快到目标时再慢下来。夹爪在这段时间保持张开。选择关节空间轨迹，是因为起点和终点都是明确的关节配置，适合第一次移动到一个已由 IK 算好的预抓取姿势。

如果机械臂到位后球仍发生沉降，代码重新读取球心并重新算一次 IK；当前抓取点与更新后目标相差超过 3 mm 时，再走一次关节轨迹。

### 6.2 一般末端移动：给抓取点一条位置路，再给夹爪一条转向路

[move_grasp_point()](../scripts/yam_pick_ball.py#L927) 的输入是目标抓取点位置、夹爪目标朝向、夹爪开合目标和移动速度。函数先读取真实起点位置与当前朝向，再生成一串中间目标点。路径结束时间由位置移动需要的时间与旋转需要的时间共同决定，取两者中较长的时间，确保平移和转动能在同一段运动里完成。

位置的每一步目标来自起点到终点的插值：

    waypoint = start + α × (target − start)

smooth=True 时，α 使用 3u²−2u³，让运动在起点和终点更平缓；smooth=False 时直接按进度线性变化。夹爪朝向不是把旋转矩阵里的数字直接相加，而是先转成四元数，再用 SLERP 从当前朝向平滑转到目标朝向。可以把它想成手臂一边把手移向目标，一边让手掌逐步转成需要的方向。

运动时间根据抓取点的直线距离除以参考平移速度计算，也根据起终朝向的角度差除以 ARM_ORIENTATION_SPEED 计算；再用 motion_steps 调整总时长。motion_steps=240 是默认时间倍率，480 大约会让轨迹用时翻倍。平移速度是规划时间的参考值，真实速度仍会受 smooth 曲线、关节驱动、力矩和接触影响。

每个中间目标都会进入在线闭环：读实际关节角，计算当前抓取点位姿和雅可比，DLS 求关节变化；再把关节目标限幅并限制在关节范围内，交给 position drive。路径走完后最多再推进 120 步收敛；抓取点位置误差、夹爪朝向误差和关节速度连续 3 步都满足阈值，才认为到位。

### 6.3 抓球搬运：围着基座走连续极坐标路线

夹住球以后，[move_ball_on_continuous_polar_path()](../scripts/yam_pick_ball.py#L1077) 不直接让夹爪沿球到方块的直线移动，因为直线可能穿过桌心底座。它把球相对机器人基座的位置写成半径 r 和方位 θ，并从起点与目标点分别计算两者：

    r = 球心到基座 XY 的距离
    θ = 球心相对基座的方位角

然后让半径和方位共用同一个平滑进度 α：

    α = 3u² − 2u³
    r(u) = r_start + α(r_goal − r_start)
    θ(u) = θ_start + α(θ_goal − θ_start)
    XY(u) = base_XY + r(u) × [cos θ(u), sin θ(u)]

因此球会沿着一条弯曲的环绕路线从起点移动到目标，而不是由多个独立小段拼接。全程只在整条路线开始和结束时平缓加减速，避免每经过一个中间路点就重新减速再启动。代码还会检查起点和目标方位是否需要绕过 joint1 限位；方位差超过 π 时拒绝这条搬运路线。

搬运时夹爪高度保持在开始搬运时的高度，夹指继续朝下，水平朝向跟着当前路线方位转动。每个物理步都读取软球真实球心：如果球比夹爪目标位置偏了一点，就把这段偏差补到夹爪 XY 目标里。这样控制目标跟随球，而不是只让夹爪到达名义终点。目标增量使用 TRANSFER_DLS_GAIN 放大后仍受单步上限和关节限位约束，实际轨迹由仿真反馈继续修正。

### 6.4 把轨迹设置对应到抓取各阶段

| 阶段 | 目标轨迹怎么设 | 这样设置的原因 |
| --- | --- | --- |
| PRE_GRASP | 球心上方 0.10 m；离线 IK 求关节终点，再用关节空间 smoothstep 接近 | 离物体较远，先以稳定姿势安全靠近 |
| DESCEND | 先到球上方 2.5 cm，再到球心；最后一段速度降至 0.25 m/s | 接触敏感，分段控制并降低最后下降速度 |
| LIFT | 从当前抓取点沿世界 Z 上移；smoothstep，参考速度 0.35 m/s | 减少起停冲击，并检查软球是否跟着抬升 |
| TRANSFER | 固定抬升高度，按 r、θ 同步插值，参考速度 0.30 m/s（用于估算用时） | 绕开底座，降低夹持软球时的搬运速度 |
| LOWER | 先到支撑面上方约 15 mm，再按实际球底净空分小步下降；最后速度 0.030 m/s | 软球会变形，按实际接触高度精细落放 |
| RELEASE | 机械臂保持，joint7、joint8 从闭合位置线性张开；释放速度 0.012 m/s | 慢速卸载，减少夹指把球带偏的机会 |
| RETREAT | 张开夹爪后，抓取点向上移动约 0.10 m | 让夹指离开球和支撑面，降低撤离时再次碰撞的风险 |

不同阶段虽然使用不同的几何路径，但实际关节目标都要经过关节限位、DLS 和 position drive。轨迹定义“希望末端按什么顺序到哪里”，物理反馈决定机械臂真实移动了多少；偏差超限或超时会触发对应阶段的错误判定。

# 三、逐阶段解释代码如何处理

## 7. 采样与 reset：为每轮创建新的初始条件

[sample_object_positions()](../scripts/yam_pick_ball.py#L581) 分别在机器人周围的环形工作区采样方块和软球。候选点需要同时满足三类约束：物体带几何余量完整位于桌面上；两物体水平距离至少 0.18 m；球和方块的方位差不超过 π。最后一条与 joint1 限位有关，避免必须走很长的绕行路径。

[reset_episode()](../scripts/yam_pick_ball.py#L624) 将机器人八个关节写回默认位置，速度清零；方块写入新位姿并清零速度。软球需要复位整组节点，而不是单一刚体位姿：代码调整节点 XY 使平均球心落到采样位置，同时根据最低节点高度和 BALL_PARTICLE_RADIUS 调整 Z，使球底略高于桌面；所有节点速度清零。多轮运行时，程序可以复用首次稳定后的球形状模板，再平移到新位置。

本阶段输出不是“球已经可抓”，而是一个允许物理自然沉降的初始状态。

## 8. 场景 settle：确认方块与软球都停止明显运动

[wait_until_scene_settled()](../scripts/yam_pick_ball.py#L786) 循环调用 step_scene，并在每一步计算两种物体的指标。

| 对象 | 读取的真实状态 | 主要判据 |
| --- | --- | --- |
| 方块 | 旋转后的最低角点、质心线速度、角速度、XY 位置 | 底面接近桌面、速度足够小、仍在桌面范围内 |
| 软球 | 节点平均位置、平均节点速度、最大节点速度、最低节点高度 | 球底接近桌面、整体及局部运动都足够小、窗口内 XY 漂移足够小 |

方块和球必须在同一步都满足要求，稳定计数才继续累加；任一条件失效，计数归零。球心窗口内的 XY 漂移若过大，也会重新计数。reset-only 模式默认要求连续 30 个稳定主步；为抓取准备时采用另一组阈值，要求连续 12 步。函数还要求至少推进 --steps-per-episode 指定的步数，并设置最多等待时间。这样不会因为某一帧速度偶然接近零，就把正在反弹或缓慢滑动的软球误认为稳定。

如果球或方块移出桌面、发生明显穿透或等待超时，函数报告对应的速度、接触净空和稳定步数。通过后打印 SCENE_SETTLED，进入下一阶段。

## 9. PRE_GRASP：先找到可达姿态，再跟踪沉降后的球心

[pick_and_lift_ball()](../scripts/yam_pick_ball.py#L1411) 先把预抓取点设置在球心上方 0.10 m。目标姿态由 [radial_grasp_rotation()](../scripts/yam_pick_ball.py#L1048) 生成：想象夹爪像一只从上方伸下来的手，手指朝下；球在机器人不同方向时，手掌的水平朝向也跟着转过去。离线 IK 再检查机器人能不能摆成这个姿势并到达预抓取点；位置或朝向误差超过容差，就在接触球之前结束本轮。

IK 合格后，execute_arm_trajectory 让机械臂沿关节空间平滑轨迹到达预抓取配置，夹爪保持张开。机械臂运动可能扰动场景，软球也可能继续轻微沉降，因此程序再次等待抓取准备条件，重新读取 ball_center 并重新求目标。若当前抓取点距离更新后的目标超过 3 mm，则再次执行接近轨迹。

进入 DESCEND 前还检查实际抓取点与目标距离不超过 5 mm，并用夹指内侧实际间距确认球能进入夹爪。这里同时对照仿真中的 gripper 位置和项目自写 FK 的 gripper 位置；两者偏差过大说明模型坐标、URDF 参数或资产变换可能不一致。

## 10. DESCEND：分两段靠近球，闭爪前检查对中

下降先到球心上方 2.5 cm，保持夹爪张开并使用平滑位置路径；再以 DESCEND_SPEED = 0.25 m/s 移到球心对应的抓取位置。两段都通过 move_grasp_point 的 FK、雅可比和 DLS 闭环完成。

到位后，程序检查末端目标误差是否在 5 mm 内，球相对本次下降目标的水平移动是否在 3 mm 内，并用 check_ball_in_gripper 检查球心相对夹指中点的位置及软球尺寸。这些检查针对一个具体风险：末端虽然到位，却在下降过程中把球碰偏，随后闭爪会抓空或从侧面挤走软球。条件不满足时立即停止本轮，不进入 CLOSE_GRIPPER。

## 11. CLOSE_GRIPPER：根据形变目标闭爪

[hold_grasp()](../scripts/yam_pick_ball.py#L1267) 保持机械臂不动，只让两根夹指慢慢合拢。程序根据小球直径和材料软硬度估算一个夹持间距：按当前参数，8 cm 的球预计压缩约 8.8%，夹指间距先设在约 7.3 cm；随后每侧再多闭合 0.7 mm，给软球留出夹持余量。

这是经验估算出的夹爪位置，不是实时测力控制。闭合后，[grasp_geometry_metrics()](../scripts/yam_pick_ball.py#L889) 测量实际夹指间距和球在夹持方向上的宽度；接着 QUICK_GRASP_CHECK 检查球是否还在夹爪中、是否明显变形或滑动，并要求状态连续稳定约 0.1 秒。

## 12. QUICK_GRASP_CHECK：确认球稳定留在夹指之间

[quick_grasp_check()](../scripts/yam_pick_ball.py#L1355) 在夹爪保持闭合时继续推进物理，最多等待 120 个主步。每步检查：

1. 球心仍靠近两夹指中点，软球的节点包围盒没有出现异常压扁或拉长。
2. 实测夹指 gap 已明显小于张开 gap，且与球在夹持轴上的宽度及粒子接触包络相符。
3. 夹指速度足够低，球相对夹指中点的速度不超过 0.003 m/s。
4. 上述状态连续保持 12 个主步。在 120 Hz 主步频率下约为 0.1 s。

若任务设置为 --stop-after-hold，到这里即可返回，并明确标记“完成闭爪保持，但未验证抬升成功”。否则进入 LIFT。

## 13. LIFT：末端与球都必须升高

抬升前记录球心和抓取点。默认目标抬升高度为 0.03 m；若下一阶段要放到方块上，代码会按当前球底与方块顶面的高度差增大目标，预留搬运净空。move_grasp_point 保持抓取姿态、平滑向上运动，并在每个物理步检查球仍在夹爪中。

运动结束后，再调用 quick_grasp_check。与闭爪后的检查相比，此时还额外要求球底高于桌面至少 2 mm，球心实际升高量达到本次命令高度的至少 85%。main 再检查自写 FK 与仿真 gripper 位置的偏差及实际升高量。这样能够识别“机械臂抬起来、球却留在桌上”的情况。

## 14. TRANSFER：绕基座搬运，并持续用真实球心修正

若球到方块顶面的净空不足，先执行 RAISE_FOR_TRANSFER，确保球有足够越过方块的高度。随后以球和目标相对机器人基座的极坐标为基础，计算半径变化量与方位角变化量。joint1_compatible_bearing 会为目标方位选取处于关节安全区的等价角；若实际方位变化超过 π，则不执行该搬运。

连续搬运时，半径与方位角共享一次 smoothstep：

    α = 3u² − 2u³
    r(u) = r_start + α(r_goal − r_start)
    θ(u) = θ_start + α(θ_goal − θ_start)
    XY(u) = base_XY + r(u) × [cos θ(u), sin θ(u)]

这种路径围绕桌心机器人移动，避免从球到方块的直线穿过基座。夹爪保持抬升高度，手指仍朝下，手掌的水平朝向随着绕行方向逐步转动。每个物理步重新读取实际球心，用期望球心与实际球心的差调整抓取点目标，然后用 DLS 求关节目标。夹持中的球若发生轻微滑移，控制目标仍以球的位置对正，而不会只让夹爪到达规划终点。

路线结束时，要求实际球心 XY 与目标误差不超过 2 mm、末端姿态误差合格、关节速度降低，并连续保持 3 步。若仍有小偏差，put_ball_back 最多做三次 BALL_ALIGNMENT_CORRECTION；仍达不到要求就报告搬运对正失败。

## 15. LOWER：根据软球与支撑面的实际净空下放

目标支撑面可以是桌面，也可以是方块顶面。放到方块上时，代码使用方块当前位姿把软球节点转换到方块局部坐标系，计算球底到方块顶面的净空；放回桌面时计算球底到桌面的净空。这样即使方块受力发生微小移动，也能基于当前支撑位置判断。

下降分为两段：先较快接近到距支撑面约 15 mm，再以 PLACE_SPEED = 0.030 m/s 小段下放，每段后重新测净空。允许的释放接触区间约为 −1.5 mm 到 +0.5 mm；如果检测到超过允许程度的穿透，或无法到达目标区间，就停止释放。到达后继续保持数个物理步，并复查球底高度没有显著变化。

这里的目标不是某个固定的 gripper Z 数值。软球会压缩，方块可能微动，所以阶段切换依据的是软球节点与实际支撑面的几何关系。

## 16. RELEASE_SETTLE 与 RETREAT：卸载后再撤离

RELEASE 使用 PLACE_RELEASE_SPEED = 0.012 m/s 缓慢张开两指；期间记录球心相对目标支撑面的位置和最大漂移。放回桌面模式还要求球心误差与释放时漂移处于较小容差内。张开后，代码继续推进物理，直到夹指真实 gap 大于球在夹持轴上的宽度加接触包络余量，确认夹指已完全离开球。

夹指清出之后不立即撤离。RELEASE_SETTLE 会保持机械臂静止，检查球相对支撑面的水平速度和最大节点速度，要求连续 12 步稳定；最多等待 90 步。放回桌面模式若超时则失败。放到方块模式会记录未完全稳定的信息，随后仍以最终是否受到方块顶面支撑为主要验收条件。

RETREAT 将张开的夹爪向上撤离约 0.10 m。方块放置模式下，特定的撤离运动超时可记录为警告，程序仍会继续检查球是否留在方块上；碰撞异常及数值异常仍会抛出。

## 17. 最终验收与下一轮

放回桌面时，程序再次调用 wait_until_scene_settled，要求球与方块恢复稳定，并持续监控球相对原位置的误差。放到方块时，夹爪撤离后还观察 60 个主物理步；随后在方块局部坐标系中计算软球节点到有限方块顶面的接触距离，要求球心在顶面上方、球与顶面仍有合理接触。放置成功打印对应的 YAM_DEFORMABLE_BALL_ON_BLOCK_OK 或 YAM_DEFORMABLE_BALL_PUT_BACK_OK。

main 最后检查物体仍在有效场景范围，记录本轮采样位置、最终球心、沉降步数、运动结果和失败快照，并打印 EPISODE_COMPLETE 或 EPISODE_FAILED。全部轮次结束后，用 EPISODE_SUMMARY 汇总完成、沉降、抓取和放置的数量。

# 四、场景设置、pick range 与软球参数

## 18. 仿真场景与物理求解器

[make_sim()](../scripts/yam_pick_ball.py#L405) 将 MJWarp 刚体求解器与 VBD 软体求解器设为双向耦合：机器人和动态方块参与刚体求解，软球由 VBD 处理；接触时夹指推动软球，软球也对夹指产生反作用。主物理频率为 120 Hz，每个主步再细分为 10 个 Newton 子步。

[spawn_scene()](../scripts/yam_pick_ball.py#L458) 建立静态桌子、固定基座机器人、质量为 0.12 kg 的动态方块及 VBD 软球。机器人基座 XY 在桌面中心，Z 与桌面顶部齐平。程序在运行时将两侧指尖的网格碰撞近似设为 convex decomposition，以改善指尖与软球的接触几何；磁盘上的 USD 资产不因此改变。

## 19. pick range：为什么在环形区域采样

桌面尺寸为 1.50 × 1.50 m，顶部高度为 0.04 m。机器人位于桌心，球和方块均按半径 r、方位 θ 采样：

    x = robot_x + r cos θ
    y = robot_y + r sin θ

| 参数 | 当前值 | 设计原因 |
| --- | --- | --- |
| OBJECT_RADIUS_RANGE | 0.30～0.43 m | 内圈避开底座，外圈保持在当前验证的可达范围内 |
| OBJECT_BEARING_RANGE | −2.40～3.00 rad | 径向抓取时给 joint1 的关节限位留余量 |
| MIN_OBJECT_PLANAR_DISTANCE | 0.18 m | 避免球与方块初始重叠，并形成有意义的搬运距离 |
| MAX_TRANSFER_BEARING_DELTA | π rad | 排除受 joint1 限位影响、需要过长绕行的组合 |
| SAMPLING_MAX_ATTEMPTS | 100 | 有限次数内找不到有效位置就明确报错 |

候选物体还要带自身尺寸和接触包络余量完整落在桌面内。通过这些几何筛选，仅说明候选场景适合尝试；目标的完整位姿仍须由预抓取 IK 和运行中的真实误差检查判断。当前范围属于该配置下的任务工作区，不表示机械臂所有理论可达位置。

## 20. 软球材料及接触参数：每组数控制什么

| 参数 | 当前值 | 作用与设置考虑 |
| --- | --- | --- |
| BALL_RADIUS | 0.04 m | 球直径约 8 cm，小于约 9.4 cm 的夹爪最大张开间距 |
| BALL_DENSITY | 500 kg/m³ | 决定球的质量规模，影响抬升和搬运惯性 |
| BALL_YOUNGS_MODULUS | 50 kPa | 控制软球受力变形的难易程度 |
| BALL_POISSONS_RATIO | 0.35 | 影响受压时横向形变；与 E 一起换算 VBD 材料参数 |
| BALL_PARTICLE_RADIUS | 0.006 m | VBD 节点的接触包络半径，也参与球底净空计算 |
| BALL_INTERNAL_DAMPING | 0.01 | 球体内部形变过程的耗散 |

VBD 材料接口使用 Lamé 参数，因此源码在建场景时按下式把杨氏模量 E 和泊松比 ν 转换为剪切模量 μ 与第一 Lamé 参数 λ：

    μ = E / [2(1 + ν)]
    λ = Eν / [(1 + ν)(1 − 2ν)]

还要区分另外三类参数。soft_contact_ke、soft_contact_kd、soft_contact_mu 控制夹指等刚体与软球之间的接触，其中当前摩擦系数设置较高以支持夹持；桌面与方块的 SUPPORT_CONTACT_STIFFNESS、SUPPORT_CONTACT_DAMPING 控制支撑接触的恢复和振荡；arm/gripper actuator 的 stiffness、damping 控制关节 position target 的跟踪。BLOCK_SETTLE、BALL_SETTLE 与 QUICK_GRASP 等阈值只改变“何时判定通过”，不会直接使物体在物理上更稳定。

这些具体材料和接触数值是当前仿真任务的配置与调参结果。源码没有提供真实软球材料的标定实验，因此汇报时可以解释每类参数的物理作用和选值目的，不应把这些数值表述为真实材料测量值。

## 21. 总结

工程把三层闭环连在一起：运动学把目标抓取点转为关节目标；Newton 仿真产生机器人、软球和方块的真实下一步状态；每个任务阶段再依据物理状态决定继续、修正或失败。抓取成功取决于球是否稳定留在夹指中并实际离桌；放置成功取决于释放、撤离后球是否仍由目标支撑面承托。

当前系统使用仿真真值获得球与机器人状态，采用预设任务阶段和 DLS 局部 IK；展示结果时应限定在当前球材料、夹爪几何和采样工作区内。本文中的采样半径上限按源码使用 0.43 m；现有参数参考文档中的 0.45 m 为旧值。
